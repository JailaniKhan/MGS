## Objective
- Fix report calculation bugs (Stock, P&L, Balance Sheet, Aging, Daybook, Backup) caused by a `status='completed'` filter mismatch and other logic errors in the MGS Laravel/NativePHP app, then enable real WhatsApp/SMS reminder delivery.

## Important Details
- Project: Laravel 13.14.0 / NativePHP at `D:\Mobile App\MGS`, PHP 8.5.7, SQLite.
- All orders/purchases in DB have `status='pending'` (none `completed`) — root cause of zero-value reports. App elsewhere excludes only `cancelled`, so `status != 'cancelled'` is the correct filter.
- Multi-tenant via `BelongsToUser` trait; many tables lack `user_id` (isolation gap, not fixed). The trait sets `user_id` from `Auth::id()` on creating and adds a global scope filtered by `Auth::id()` — works only when a user is authenticated (web/UI context). Tinker/queued jobs have no Auth, so reminder creation fails there (UI is fine).
- Lang files `resources/lang/{en,fa,ps}/messages.php` (545 keys each after dedup).
- `remaining_amount` is an accessor on Order/Purchase (not a column).
- Messaging architecture: `ReminderController` → `ReminderService::sendReminder()` (creates `Reminder` row, status pending→sent/failed) → `EasySendSmsDriver` (SMS) or `WhatsAppService` (WhatsApp). `SendPaymentReminderJob` is a SEPARATE lighter path that just sends via `SmsGateway` (no Reminder record / history). `EasySendSmsDriver implements SmsGateway`, bound in `AppServiceProvider`.
- **EasySendSMS REST API v1 (the `.com` commercial platform the user uses)**: `POST https://restapi.easysendsms.app/v1/rest/sms/send`. Auth = API key in the **`apikey` header** (NOT username/password — that was the separate free `.app` HTTP API). Body is **JSON**: `from`, `to` (intl format, no `+`/leading zeros), `text`, `type` (`text`|`unicode`). Balance endpoint: `GET /v1/rest/sms/balance` (same `apikey` header) returns `{"balance":N}`. Invalid key → `4003`; throttle → `429`; bad sender → `4014`; no credits → `4015`. `.env` uses `SMS_API_KEY` (+ optional `SMS_URL`). Real key is now in `.env` (do NOT commit).
- WhatsApp: Meta Cloud API `graph.facebook.com/v18.0/{phone_number_id}/messages`, bearer token `WHATSAPP_API_KEY`, JSON `{messaging_product, to, type, text.body}`. `.env`: `WHATSAPP_API_KEY`, `WHATSAPP_PHONE_NUMBER_ID` (still EMPTY).
- These `.env` credential keys are currently EMPTY (not yet provided by user).
- PowerShell: no `<` redir; use `php artisan tinker --execute="require 'tempfile';"`.
